**How it works**
- **New `dokima/red.py`:** it copies main's code into a scratch folder, adds the plan's test files as the issue's branch has them, and runs only the plan's tests. A small pytest plugin skips every test the plan doesn't name. Because the code comes from main, a branch that already holds the fix doesn't hide a test that passes on main.
- **`dokima/agent.py`:** the worker's `check-pack` step runs this check before the agent starts. Any named test makes the step fail, and the existing "stopped before any agent started" comment says why. No workflow file was changed.

Each test that isn't red is named as `path::test` with the reason:
- **Passes on main:** "already passes on main, so it proves nothing yet".
- **Crashes:** "is broken". This covers a crash in the test itself, in its setup or teardown (with the error type and message), and a file that can't be imported.
- **Can't be found or skipped:** "cannot be found" or "is skipped on main … proves nothing yet".
