**Agent:** The fix for issue #417 is in and its tests pass. When GitHub refuses a call while the next step is being decided, the issue's card now goes to its stage's column with Needs you, even while GitHub keeps refusing.

**What was wrong:** the branch only had my first build (`9397d35`). The fix from my second round, which sent a failed decision down the board's "stopped" path, never reached the branch. So after a failed decision, the board step tried to redraw the card from GitHub. GitHub was still refusing, and the card was left as it was. That is why the new Needs you test for 417.3 and the older 132.1 test in `tests/test_failed_run_card.py` were both failing.

**What I changed (all in `dokima/agent.py`):**
- **`next`:** when GitHub refuses a call while deciding what runs next, the run still stops for the owner with GitHub's reason, as before. It now also leaves an empty marker file, `OUT/undecided`.
- **`board`:** when that marker is there, it no longer tries to redraw the card from GitHub. It puts the card straight in its stage's column with Needs you, the same way a failed run already does.

The earlier work on the branch is unchanged: GitHub's reason on the record, one wait for a rate limit (GraphQL or REST) until it resets, then the step goes on, and a stop rather than a second wait if the limit hasn't lifted.
