> 1 The planner's, the worker's and the reviewer's hand-backs all take the same found-issues field (issues_found: title, why, evidence), and each agent's prompt describes it. Every issue listed there is filed during that agent's own run, with no command, as its own GitHub issue. The issue takes the finding's title and has exactly two labels, parked and filed-by-dokima, even on a repo that doesn't have those labels yet. A hand-back that lists no issues files none. 
> 
> 2 Each filed issue says where it was found (the issue the run worked on, plus its pull request when there is one) and which agent found it. It carries the finding's why and evidence, and links the comment that holds the record of the run that found it. 
> 
> 3 A filed issue gets nothing beyond filing: it isn't made a sub-issue, gets no blocked-by link, doesn't go on autopilot even when the issue it was found on is, and no stage starts on it. 
> 
> 4 The same finding is never filed twice. A title Dokima has already filed, open or closed, is not filed again, ignoring letter case and spacing. That holds whether it repeats within one hand-back or comes back in a later run of any agent. New findings next to it are still filed. 
> 
> 5 The run's card names each filed issue by its number and no longer calls the findings proposals. When GitHub refuses to file one, the card still posts and names that finding with GitHub's reason.
