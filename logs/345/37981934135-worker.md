The fix is in `.github/workflows/card.yml`. `dokima/card.py` didn't need to change. `AGENTS.md` and my worker instructions both say not to edit `.github/`, but the approved plan puts `card.yml` in scope. A merge can only start a redraw from that file, so I followed the plan. Per `AGENTS.md`, a build that changes a workflow file pauses until the owner approves it on GitHub, so this one will wait for you.

The change has three parts:
- **New trigger:** the workflow now also starts when a pull request closes (`pull_request_target`, `closed`). GitHub runs that from main's copy of the workflow, and the checkout step takes main, so the pull request's own code never runs.
- **The job's `if:`:** a merged pull request now gets through even when the bot merged it. Before, the bot's events were skipped. Its own edits of the card still start nothing.
- **`PR_NUMBER`:** falls back to the merged pull request's number, so `card.py` redraws only that pull request and its issue, and no other card.
