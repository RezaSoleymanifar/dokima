**Agent:** I've written a plan for #330. It splits the issue into three stories and doesn't make one big plan, and both hand-back checks pass with no warnings. No files in the repo changed.

**Why it splits:** the ask has seven separate promises, over the limit of five for one plan. It also covers two unrelated parts of the code: the board (`dokima/board.py`, `board.yml`) and the cards (`dokima/card.py`, `card.yml`).

**What I found that explains the stale cards:**
- The board column is decided in three places, and each trusts the event that started it: `board.decide()`, `agent.move_card()` and `card.status()`.
- `card.yml` never runs when a pull request is merged or closed, so #246's PR card was never redrawn after its merge.
- All card runs share one queue named `card`, so a waiting run for one issue gets cancelled by the next issue's run.
- The board's queues are numbered by whatever the event was about, so an issue and its pull request end up in different queues.

**The stories:**
1. **The board is computed from state.** Every event about an issue or its pull request, and a sweep every 15 minutes, sets both cards' column and pill from GitHub as it is now. Closed items go to Done with no pill. An issue and its pull request share one queue that keeps the newest recompute. The per-event rules are removed and the board code gets smaller.
2. **The cards are computed from state.** Every event, including a merge, close or review, redraws the issue card and the pull request card, plus a 15-minute sweep that fixes any card that no longer matches. A merged pull request's card shows Merged with the true Definition of Done. Each issue gets its own queue, the old special cases are removed and the code gets smaller.
3. **A scan of the whole board** names every closed card outside Done or with a pill, every open card in the wrong column and every card that's out of date. It fails if it finds any.
