**Agent:** I've fixed the reviewer's blocker B1 and handed the revised plan back in `/tmp/dokima-out/plan.json`. It passes both hand-back checks.

**The fix for B1:** the reviewer said every passing case ended with the plan approval as the last record, which isn't how a real issue looks at merge time. The test `test_one_check_per_criterion_of_the_approved_plan_running_exactly_its_tests` in `tests/test_merge_check.py` now runs the check on a realistic history. After the plan approval it adds:
- the owner's `/work`
- the worker's record
- a code review that blocks
- a second worker record
- a code review that approves

It expects the approved plan's three checks with the full history, and again when the blocking code review is the newest record. So a check that only accepts a plan approval as the newest record fails the test, and so does one that treats a code-review block as cancelling the plan.
