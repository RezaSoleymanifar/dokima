**What it does** (`dokima/audit.py`, new):
- **The command:** `python3 -m dokima.audit OWNER/REPO` reads through `gh` the labels, the board's options and views (the board named in `DOKIMA_BOARD`), main's branch rule and the app's permissions.
- **One line per difference:** a missing setting, a changed color, description, layout or filter, a missing or extra required check, and a missing or broader permission. Each line names the setting, what it is now and what Dokima needs. Matching settings, and labels, options and views the manifest doesn't declare, get no line.
- **When something is off:** it opens one Setup issue, pins it and sets its card to Needs you. A later run finds that same issue by a hidden marker in its body, updates it and marks it Needs you again.
- **When nothing is off:** with no Setup issue open, it writes nothing to GitHub. If one is open, it posts one comment saying nothing is off and closes it.
- **Code owners:** the Setup issue mentions exactly the owners of `*` in `.github/CODEOWNERS`. Every `gh` call names only the repo being audited.
- **Failed reads:** a read GitHub refuses or fails (a 403, a 502, or a board that isn't there) becomes its own "could not be verified" line with GitHub's reason, and that opens or keeps open the Setup issue. Only GitHub's "Branch not protected" answer counts as "main has no rule".

**Change to the manifest:** I added one entry to `dokima/manifest.py`. The audit reads `repos/OWNER/REPO/installation`, which the manifest's guard couldn't tie to any permission, so the full test run would have failed. I declared it as needing no app permission, because GitHub answers that call only to the app's own key. The plan's out-of-scope list already says the workflow can't read it yet, so until #285 the permissions line will say it could not be verified.

**Choices beyond the plan's wording:**
- Without `DOKIMA_BOARD`, the command stops with an error rather than auditing without the board. The plan leaves that case out of scope.
- It finds an existing Setup issue by listing up to 1,000 open issues rather than using GitHub search. Search can lag behind new issues, so two runs close together could open two Setup issues.
