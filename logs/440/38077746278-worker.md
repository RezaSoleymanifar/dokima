**Agent:** When a plan is approved on [#440](https://github.com/dokima-dev/dokima/issues/440) (re-running checks after plan approval), every check on the open pull request's head now runs again by itself. The 5 new tests and the 3 older plan-check re-run tests all pass (8 passed, slow ones included). I ran only those two files, not the full suite, which runs at the merge gate. The hand-back is in `/tmp/dokima-out/work.json` and passes both checks. I raised nothing, and there were no open blockers to answer.

All of the change is in `dokima/agent.py`. The old `rerun_plan_check` is replaced by `rerun_checks`, and `recheck` now calls it.

- **Which runs:** only runs on the current head that a push started (the `pull_request`, `pull_request_target` and `push` events). For each workflow, only its newest run is re-run, in full and once. Runs on older commits, and runs started by a review, a comment or another workflow, are left alone.
- **A run still going:** it is stopped, then re-run once GitHub reports it finished. If it is still going after 5 minutes, that counts as a refusal and the pull request says why.
- **A permission refusal:** "Resource not accessible by integration" gets exactly one comment on the pull request, however many checks were refused. It says Dokima's GitHub App needs Actions set to Read and write, accepted on its installation. The link is the organization's installations page or the personal one, depending on who owns the repo.
- **Any other refusal:** one separate comment lists each check with GitHub's own words and never mentions the permission setting. If both kinds happen at once, the pull request gets two comments, one of each.
- **No open pull request:** nothing is stopped or re-run and nothing is posted.

I also changed the line printed when a plan wasn't approved, from "the plan check stays as it is" to "the checks stay as they are", and shortened three docstrings that the hand-back check said were too long.

The 5-minute wait has only been tested against a fake GitHub that finishes a stopped run instantly. Two things on the real one are untested: how long a stopped run takes to finish, and whether GitHub accepts the re-run straight after.
