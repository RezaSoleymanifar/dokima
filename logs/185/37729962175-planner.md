**Agent:** I've written the plan for #185 with seven tests, and the hand-back check passes. On today's code all 7 new tests fail because the feature is missing, and the other 270 tests pass.

**User story:** Each agent run has one card on the issue (or its PR) that turns from working into its result, so you no longer wait in silence for a comment to appear.

**Acceptance criteria:**
- **185.1** When the agent's machine is ready, the card says working, with the running icon and the start time in UTC. It goes on the PR when the run's record goes there.
- **185.2** At the end, that same comment is edited into the run's record: done with the passed icon, or failed with the failed icon and why, then its Next line. That run leaves exactly one comment.
- **185.3** The card goes up right after the code-owner check. A run that stops before its agent starts edits that card into why it stopped plus "Fix the cause, then give the command again." It never posts a second comment.
- **185.4** Every state of the card shows an icon from `dokima/icons/`. No emoji and no reactions anywhere.

**Non-functional:**
- **185.5** A card that is still running never reads as a record.
- **185.6** If the card can't be posted or edited, the run still goes on and posts its result as a record.
- **185.7** I added this one: the bot's key used to put the card up is revoked before the agent starts. Today that key only exists after the agent finishes, so posting early would otherwise leave a live bot key on the machine while the agent works.

**Scope:** `.github/workflows/agent.yml`, `dokima/agent.py`, and an optional new `dokima/icons/queued.svg`.

**Tests:** They're in `tests/test_live_card.py` and run `agent.yml` step by step on a fake GitHub, so they check what the run actually posts rather than reading the workflow text. To make that possible I extended the existing harness in `tests/test_start.py`:
- The fake GitHub now keeps every comment with each version as it's edited in place, and logs which key made each call.
- The fake agent records what was on GitHub, its own environment and the time when it started.
- It now handles step ids with a dash, which it couldn't before.

No existing test function changed, and they all still pass.

I also built a rough version of the change to confirm the tests can pass. All 277 passed with it, and I then reverted it.

**One question for you:**
- **When should the card first appear?** I assumed it goes up at the start of the run, so a run that fails while getting ready edits it, because the issue says such a run "updates that card". Answer with `/plan` if you want it to appear only when the agent starts.

**Two concerns:**
- **Key timing:** this is the reason for 185.7. Posting the card early needs the bot's key before the agent runs, so the plan mints a short-lived key for each update and revokes it before the agent starts.
- **Workflow push:** the worker has to change `agent.yml`, and AGENTS.md says the bot can't push workflow changes yet. That pause for your approval is still planned, so you'll likely need to step in when the worker's push is refused.

**Out of scope:** commands that fail in the listener, cancelled runs, the card at the top of the issue and the board. A worker's first-run card also stays on the issue after it opens the PR.
