**How it works now:**
- **Right after the code-owner gate**, the run posts a "getting ready" card. It goes on the issue, or on the PR if one is open and this is the worker or the PR reviewer.
- **Just before the agent starts**, the same comment is edited to "working since YYYY-MM-DD HH:MM UTC" with the running icon.
- **At the end**, that same comment is edited into the run's record. A run that stops before its agent starts also edits the card, into its not-started record, which says why and "Fix the cause, then give the command again."
- **Icons:** records now show the passed or failed icon. I added `dokima/icons/queued.svg` for the getting-ready state.
- **The card is never read as a record.** It has its own marker (`<!-- dokima-live -->`) and no JSON fold, so packs, the river and approvals skip it until it becomes the record.
- **Keys:** each card update before the agent uses its own short-lived bot key, which is revoked at the end of that step (`gh api -X DELETE installation/token`). No bot key is live while the agent works, and the record is still posted with the key made after the agent finishes.
- **If the card can't be posted or edited**, the run logs a warning and carries on, and posts the record as a new comment at the end.
