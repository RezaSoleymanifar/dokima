> # Autopilot's reaction to an issue closing, usually because its pull request merged. Code reads every issue on
> # autopilot from GitHub: a parent whose last sub-issue closed closes too, saying its whole tree is done, and that
> # close counts one level up; a done tree (its top issue closed) goes off autopilot; and every issue left on autopilot
> # whose blocked-by issues have now all closed starts its planner, with one Autopilot line where the owner would have
> # said /plan. Nothing starts twice: an issue with a record, a live card or that line is never started again.
> # Every close waits in one queue for the whole repo, which a newer run never cancels, so two merges that close
> # together never read the tree at the same moment; and since each run works from the state of every tree, the run
> # that goes also does the work of any close whose run GitHub dropped from the queue. A failure says why on the issue.
