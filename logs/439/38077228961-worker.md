**Agent:** Once a build has started on an approved plan, the issue card and the PR card now say **Work** and no longer ask the owner to say /work. All 11 tests in the plan's `tests/test_build_started_card.py` pass. Before the change they all failed.

**The cause:** `status()` in `dokima/card.py` placed the card using only the newest record. After a plan review approved, it kept saying "Plan · Needs you: Say /work to build the plan" until the worker's own record arrived, even while the worker was already building.

**The fix:** a 6-line change in `status()` that reuses the board's existing rule (`agent.started`, the same one `dokima/board.py` uses). After the newest record, if the latest stage started is Work, the card returns Work with nothing for the owner. A build counts as started by:
- a code owner's `/work`
- the bot's line `Autopilot: plan approved, starting work`
- the worker's run card, queued or working

The same words from anyone else, or a code owner's comment with no command, change nothing. So an approved plan that hasn't been built yet still asks for /work.

The other card, board and card-drawing tests pass too (278). I didn't run the full suite; it runs once at the merge gate. The hand-back is in `/tmp/dokima-out/work.json` and passes both checks, with no raises and no open blockers to answer.
