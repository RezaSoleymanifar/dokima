**The blocker:** the plan promised that both the card and the planner refuse a save that would change the owner's ask and comment why. Only the card was tested for that. The planner saves the issue body itself, with its own `gh issue edit` call in `dokima/planner.py`. A build that left that call untouched would have passed every test.

**The fix:** I added two tests to `tests/test_body.py`. Each runs the planner's post step the way the workflow does, in a temp git repo with a handed-back plan, against a fake GitHub:
- **`test_the_planner_refuses_rather_than_change_the_owner_part` (179.3):** first a good post, which must save the body exactly once, with the plan above the marker, the owner's ask unchanged and no refusal comment. Then a post where the helper refuses, which must save nothing and leave a comment on the issue giving the reason.
- **`test_the_planner_posts_its_refusal_on_the_issue` (179.5):** when the save is refused, exactly one comment with the reason must land on this issue and the body must never be written. This holds even if the run fails afterwards, so a crash with no comment fails the test.

To make this work, the fake GitHub now returns the issue body when the planner reads it. In `plan.json`, both tests are listed under their criteria and B1 is answered as fixed.
