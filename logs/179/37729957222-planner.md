**Agent:** I've finished the plan for #179 as a single user story, and both hand-back checks pass. The plan is in `/tmp/dokima-out/plan.json` and the tests are in `tests/test_body.py`.

**User story:** Owners can trust that whatever code redraws on an issue, their original ask below the marker stays exactly as they wrote it.

**Acceptance criteria:**
- **179.1:** The issue body is the card, then one fixed marker, then the owner's ask in a closed fold, exactly as written.
- **179.2:** Every redraw, by the card or by the planner, changes only the part above the marker. The ask stays identical to the last byte however many times it's redrawn, including Windows line ends, trailing spaces, old checkboxes and stray `</details>` or card markers.
- **179.3:** If a save would change the owner's part, code refuses, leaves the body as it was, and comments why on the issue.
- **179.4:** An issue with no marker gets one on its first redraw, with the whole existing body kept below it unchanged.
- **179.5 (non-functional):** A refusal is always a comment on the issue itself, never only a line in the log.

**How it would work:** a new `dokima/body.py` owns the issue body. Its `redraw` builds the new body and refuses if the owner's part would change. Its `save` either writes the body or posts the refusal comment. `card.py`'s `main()` and the planner's `render` both go through it. The 14 tests run the helper, the card's `main()` and the planner's `render` against a fake GitHub.

**Test results:** all 14 new tests fail today because `dokima/body.py` doesn't exist yet. To check they can pass, I wrote a throwaway version of the helper in a scratch copy outside the repo. With it, all 284 tests passed.

**Scope:** `dokima/body.py`, `dokima/card.py`, `dokima/planner.py`, `AGENTS.md` (to drop "(planned)" from "The issue body"), `tests/test_body.py`, `tests/test_card.py`.
