**Agent:** I blocked PR #314 for issue #264 and sent it back to the planner. The worker built what the plan asked for, but a pull request can still turn a failing test green in two ways the plan's tests don't check. I reproduced both on the step's real commands.

**What the worker did:** both checks now check out main at the top and the pull request in a `pr` folder. A new step deletes the pull request's `conftest.py`, `pytest.ini`, `.pytest.ini`, `pyproject.toml`, `setup.cfg` and `tox.ini` files and copies in main's. Only the two workflow files the plan named were changed, and the planner's tests are untouched. All 716 tests pass on the branch, including the four new ones.

**Blockers (both for the planner, because the tests are too weak):**
- **B1 (criterion 264.1): two settings files are missing from the plan.** The checks install pytest 9, which also reads its settings from `pytest.toml` and `.pytest.toml`. The plan's list leaves both out, so the step never removes them. In a scratch test, a `pytest.toml` set to collect tests without running them made a failing test exit 0. `.pytest.toml` did the same. Fix: add both to the criterion and to the test's list of attacks; the worker then adds them to the step.
- **B2 (criterion 264.2): a symlinked `conftest.py` gets through.** The step only deletes regular files, so a `conftest.py` that links to a rigged file stays in place. pytest reported "1 failed" but exited 0. The tests can't catch this, because the fake checkout they use (`tests/test_all_tests_judge.py:154`) copies a symlink as a plain file. Fix: add a symlink attack and have the fake checkout keep symlinks; the worker then deletes symlinks too.

GitHub's results for each criterion's check weren't in the pack, so I couldn't confirm the checks are green on GitHub. The 716 passes come from runs on this machine.

The review is in `/tmp/dokima-out/review.json` and passes both hand-back checks.
