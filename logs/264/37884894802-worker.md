**Agent:** Both checks now judge a pull request's tests with main's `conftest.py` files and pytest settings, and the pull request's own copies are never read. All four of the plan's tests pass: they failed before the change, and the full suite now gives 716 passed. The hand-back check on `work.json` also passes.

**What changed** (only the plan's two files; the issue asked for workflow changes):
- **`.github/workflows/full-suite.yml`**: main is now checked out at the root with no `ref:`, and the pull request's commit goes into `pr/`, where every step runs. A new step, "Use main's test setup", deletes every `conftest.py`, `pytest.ini`, `.pytest.ini`, `pyproject.toml`, `setup.cfg` and `tox.ini` in `pr/`, at any depth. It then copies main's copies back in at the same paths. Then `pytest ... tests` runs as before.
- **`.github/workflows/done-whens.yml`**: this job already had main at the root and the pull request in `pr/`. The same step now runs just before "Run this done-when's tests".

So a pull request can't add, edit or delete its way out of main's setup. Main's settings come back even when the pull request deleted them, and an edited `tests/conftest.py` is replaced by main's.

**Things to know:**
- **Setup changes only take effect after merging.** A pull request that changes `conftest.py` or pytest settings doesn't stop for you. Its change is simply ignored by both checks until it merges, and from then on it judges every later pull request. On autopilot that merge needs no approval from you. The plan reviewer flagged this and proposed an issue to make such pull requests stop for the owner.
- **The merge queue is left as #263 left it**, which the plan put out of scope. The main checkout has no `ref:`, so in the queue it gets the queued commit, setup files included.
- **One gap is still open**, as the plan's concern says: code that ends the test process with exit code 0 can still turn both checks green.
- **I only ran the workflows in the tests' simulation, not on GitHub.** They use bash arrays and GNU `cp --parents`; both work on the `ubuntu-24.04` runners.
