**Agent:** I fixed the one open blocker, B2: the plan check now rejects a split whose story has a malformed `non_functional` list, instead of passing it and crashing later when the child issues are filed.

**The cause:** `check_stories` in `dokima/planner.py` checked each story's title, user story, criteria and `depends_on`, but never its `non_functional` list. So `"none"`, `[5]` or `[{"text": 1, "why": "w"}]` got through, and `story_body` in `dokima/agent.py` crashed on it once the split was approved.

**The change:** in `check_stories`, each story's `non_functional` (empty if missing) must now be a list, and each item an object with non-empty text in both `text` and `why`. The rejection names the story and the field, matching what the check already does for a single story. That's 10 added lines in that one file and nothing else.

**Checked:** I ran it by hand against a split with `GITHUB_REPOSITORY=dokima-dev/dokima`:
