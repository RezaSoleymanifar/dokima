**Agent:** Every run now gets its card within seconds of what started it, and that run edits the same card into its record. All 300 tests pass, including the plan's five new ones and the updated `/plan` case in `test_start.py`. The hand-back check passes too.

**What changed** (only the three files the plan names: `commands.yml`, `agent.yml` and `dokima/agent.py`):

- **Commands (186.1, 186.4):** `commands.yml` has a new `queue` job. It runs only when `route` has picked a stage, and `route` only picks one for a code owner's `/plan`, `/work` or `/review`, so a stranger's comment posts nothing. The job puts up a "queued" card where the record will go: the issue, or the open pull request for the worker and the code review. It then passes the card's id to `agent.yml` as a new `card` input. The run changes that card to "getting ready" instead of posting its own, and later edits it into its record.
- **Waiting (186.2):** before posting, the new `agent queue` command looks at Dokima's live cards on the issue and its pull request. It skips its own run and asks GitHub whether each linked run is still queued or in progress. If one is, the card says "waiting for this run" with a link; if not, it says "queued". Before the agent starts, the run's card says getting ready and then working, so "waiting" is gone by then.
- **Hand-offs and splits (186.3):** the "Start the next stage" step puts up the next run's queued card and sends its id with the `dokima-next` signal, so the next run edits it. Filing a split edits the command's card into the "Split filed" record. If filing fails, the step that reports the error edits the same card to say why.
- **Fallback:** if a card can't be put up or edited, the run carries on and posts its own card as before.

Things that behave differently from before:
- `agent card … queued` is now `agent card … ready` for the "getting ready" card. `queued` now means the new queued card. `agent.yml` was its only caller, and it is updated.
- A hand-off's queued card has no link to its own run, because that run doesn't exist yet when the card goes up. So a later command can't see that run as one to wait for.
