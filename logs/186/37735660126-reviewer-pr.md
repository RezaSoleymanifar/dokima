- **186.1:** A new step runs as soon as a code owner gives `/plan`, `/work` or `/review`. It puts up a queued card where the record will go: the pull request for the worker and the code review once one exists, otherwise the issue. The run edits that same card into its record and posts no other comment.
- **186.2:** If another run on the issue or its pull request is still going, the card says it is waiting and links that run. With nothing ahead it says queued. Once the run's machine starts, the card says getting ready instead of waiting.
- **186.3:** Every hand-off the river starts puts up the next run's queued card and passes its id on, and that run updates it. Filing a split turns its one card into the Split filed record, or into the record of why if filing fails.
- **186.4:** The card only goes up when the code-owner check has picked a stage. A stranger's command or a comment that isn't a command posts nothing.

**Three notes, none of them blockers:**
- The jobs that start the run or file the split would now still start even if the command's own workflow run is cancelled.
- A hand-off's queued card doesn't link its run. So a command given while a hand-off run is still pending will say queued, not waiting. This overlaps with story 4 of #164, which handles GitHub replacing a pending run.
- With a queued card, filing a split always turns that card into a Split filed record, even if one already exists. The old guard against a second record now only applies when there's no card.
