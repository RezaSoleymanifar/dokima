**Agent:** I've built issue #478: every item under "Raised earlier" in a run's comment now starts with who raised it and a link to where, e.g. `Code review on [#462](link) raised: `, then the raise and its answer as before. The plan's tests for both criteria (478.1, 478.2) and the related ones pass locally (27 passed), and the hand-back check passes. GitHub's checks haven't run on this yet.

The change is all in `dokima/agent.py`:

- **Keeping the link:** when `pack()` builds the starting pack, it now adds each record's comment link (`url`) to that record's file in `in/`. That file is the record exactly as GitHub holds it, plus this one field.
- **Drawing the item:** a new `raised_by()` gives the name (Planner, Worker, Plan review or Code review). It adds "on [#N](link)" only when the link is a real GitHub issue or pull request comment link, taking N from the link itself.
- **The Raised earlier section:** `answered_lines()`, which draws it for every role, puts that opening on each item. An answer whose raise isn't found keeps its old line.
- **No link known:** the item just says "Planner raised:" with no link, so no wrong or empty link is ever drawn.

One limit: a record posted as a pull request review rather than a comment won't get a link, only the name. The pack is built from reviews that don't include a link. Records are normally posted as comments, so this should be rare.
