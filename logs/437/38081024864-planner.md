**Agent:** I've revised the plan for #437 to answer the reviewer's blocker (R2), and it passes both hand-back checks. One new question goes to the owner.

**The blocker.** Nothing said how the commit typed into Run workflow becomes the code that draws card-gallery's cards. The reviewer was right: card.yml always runs the default branch's copy of itself and of `dokima/card.py`. So unless the play-through puts the commit onto card-gallery first, its PASS and FAIL lines describe whatever Dokima card-gallery already runs.

**What changed in the plan.** Criterion 437.3 now says:
- `playthrough.yml` passes the checkout folder as `PLAYED` and the commit as `PLAYED_COMMIT`.
- Before the first step, the play-through puts that commit's `dokima/` folder and `.github/workflows/` files on card-gallery's default branch.
- If the `PLAYED` folder has no `dokima/`, the run fails before any GitHub call and names the folder.
- If GitHub refuses the push, no step is played: the log has one line starting `FAIL: install` with the commit and GitHub's reason, and the run exits 1.

**Tests** (in `tests/test_playthrough.py`):
- The workflow test now also checks that `PLAYED` and `PLAYED_COMMIT` are set.
- A new test checks:
  - exactly those files are picked, with their contents;
  - the commit is installed before any step;
  - a refused install logs `FAIL: install` and returns 1;
  - a folder with no `dokima/` fails before calling GitHub;
  - a real run whose install is refused names the commit and judges no step.

All 13 tests fail today only because `dokima/playthrough.py` doesn't exist yet. I also tried them against a rough scratch implementation, now deleted: the new test passed. The only 3 that failed are the ones that grade the card check, which that rough version faked.

**Question for the owner.** Nothing in the repo says how card-gallery gets its Dokima code, so I asked how the commit should get there. The plan assumes the push above. That push changes workflow files, but AGENTS.md says the bot can't push workflow changes. Until the app is allowed to write workflows on card-gallery, every run will stop at `FAIL: install`. Should it get that permission, or does card-gallery get the commit some other way?

Links stay the same: blocks [#438](https://github.com/dokima-dev/dokima/issues/438) (one workflow redraws the card on every change), relates to [#258](https://github.com/dokima-dev/dokima/issues/258) (nightly sandbox run).
