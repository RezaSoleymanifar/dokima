**Agent:** I've written the plan for #412 and four new tests in `tests/test_automerge_confirmed.py`. Both hand-back checks pass, and all four tests fail on today's code because autopilot still posts `Autopilot: merged PR #60` when nothing merged.

**The cause:** `try_merge()` in `dokima/agent.py` treats `gh pr merge` exiting 0 as a merge. With a merge queue, or a rule that waits on your approval, that command only queues the PR or turns on auto-merge. There is a second gap: after an approved code review, the issue card and the board's 15-minute recheck always show Needs you, so a queued PR would still ask you for something.

**What the plan promises:**
- **412.1:** `Autopilot: merged PR #N` is posted only after GitHub reports the PR merged. This holds for both the code review and `/autopilot start`.
- **412.2:** A PR that only joined the merge queue gets the single line `Autopilot: PR #N joined the merge queue`. The code review's card names the queue, and no card or board shows Needs you.
- **412.3:** A PR waiting on your approval gets the single line `Autopilot: PR #N waits for your approval before it merges`. The card's Next line asks you for that approval and shows Needs you: Ready for approval.
- **412.4:** When GitHub can't confirm the merge (it can't be read afterwards, or the PR is neither merged, queued nor waiting on a review), no Autopilot line is posted. The PR gets a comment that mentions you and says why, and the card shows Needs you.

**Scope:** `dokima/agent.py`, `dokima/card.py` and `AGENTS.md`. `card.py` is normally off-limits, but you asked for the card and the line to agree, and the issue card can't drop Needs you for a queued PR without changing it.
