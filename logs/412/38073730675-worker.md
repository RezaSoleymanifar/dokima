**Agent:** Autopilot now only says it merged a pull request once GitHub reports it merged. I've written the hand-back in `/tmp/dokima-out/work.json` and it passes both hand-back checks.

The bug was in `automerge()` in `dokima/agent.py`: it treated `gh pr merge` exiting 0 as a merge. With the merge queue on, or when GitHub is waiting for your approval, that command exits 0 without merging anything. The fix makes autopilot read the pull request's state from GitHub after the merge and act on what it finds:

| What GitHub reports | Line on the issue | Code review's card |
|---|---|---|
| Merged | `Autopilot: merged PR #N` | Done, as before |
| In the merge queue | `Autopilot: PR #N joined the merge queue` | Review, no Needs you; the Next line names the merge queue and doesn't mention you |
| Waiting for a required review | `Autopilot: PR #N waits for your approval before it merges` | Review, Needs you: Ready for approval; the Next line asks you to approve |
| Can't be read, or none of the above | No Autopilot line | Needs you; a comment on the pull request mentions you and gives GitHub's reason |

- **Both paths:** the same rules apply when the code review merges and when `/autopilot start` merges a whole tree.
- **Queued line clears Needs you:** the issue card and the board (including the 15-minute recompute) now treat a queued line after an approving review as nothing waiting on you. Without that line, approved work still shows Needs you as before.
- **AGENTS.md:** step 6 of the flow now records these four outcomes.
