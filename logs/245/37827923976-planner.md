**The cause:** `/autopilot start` only looks for issues to start below the one you switched on, never at that issue itself (`dokima/agent.py:1593`). That's why #229, #230, #231, #244 and this issue all said "No stage was started" until you typed `/plan`.

**Acceptance criteria:**
- **245.1:** `/autopilot start` on an issue with no plan, no sub-issues and nothing open blocking it starts that issue's planner once. The issue gets one line, `Autopilot: switched on, starting plan`, and the switch comment says planning started instead of "No stage was started".
- **245.2:** The issue's own planner does not start when the issue:
  - already has a plan;
  - has its planner running already;
  - has been split into sub-issues (its waiting sub-issues start instead);
  - is blocked by an open issue. A blocked issue then starts by itself when its last blocker closes.
- **245.3:** `/autopilot start` still picks up what is already waiting in the tree, and never starts a planner on top of it:
  - an approved plan waiting for `/work` starts its worker;
  - waiting sub-issues start their planners;
  - a pull request whose code review approved it, with every check green, merges.
- **245.4:** The whole-journey test asked for in the issue. A new issue gets `/autopilot start`, then plan, plan review, work and code review each follow by themselves until the pull request merges, with no other comment from you.
- **245.5:** Saying `/autopilot start` twice starts the planner only once.

**Two choices I made:**
- **A new Autopilot line.** The line sub-issues get today reads "blockers merged". That would be false on an issue with no blockers, so I picked a new line, `Autopilot: switched on, starting plan`.
- **The journey test goes stage by stage, not through every full run.** After `/autopilot start`, it posts each stage's record and runs the step agent.yml runs after every stage to decide what starts next. That proves each hand-off up to the merge, but the planner and worker runs themselves are not executed inside this test.
