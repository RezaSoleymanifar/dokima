**Agent:** `/autopilot start` on a new issue now starts that issue's planner, so you no longer have to type `/plan` yourself. All five of the plan's tests pass on this machine, and so does the full suite (475 passed). They only count once GitHub's checks pass on the pull request.

**The cause:** `/autopilot start` only started planning for the issues under the one you switched on, never for that issue itself. That's why #229, #230, #231, #244 and this issue all said "No stage was started".

**The change**, in `dokima/agent.py` and `AGENTS.md` only:
- **The issue itself now starts.** After switching autopilot on, it first runs the same check its sub-issues already get on the issue itself. If the issue has no sub-issues, no plan, nothing running and no open blocker, its planner starts. It posts one line, `Autopilot: switched on, starting plan`. The comment where you typed the command now says "Planning started for #N" instead of "No stage was started".
- **It never starts twice.** The check that stops an issue from being started again now also counts that new line. A second `/autopilot start` starts nothing.
- **Unchanged:** an issue that is already planned or running, is split, or is blocked by an open issue doesn't start. A blocked one starts by itself when its last blocker closes, with the usual "blockers merged" line. Picking up a waiting plan, waiting sub-issues and approved pull requests works as before.
- **`AGENTS.md`:** the Commands section now says the issue itself starts its planner, and gives the line it posts.
