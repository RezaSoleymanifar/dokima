**B1 (fixed).** The reviewer found that every test replaced `card.gather` with a fixed answer. `card.gather` is the step that fetches the records, checks, reviews and code owners from GitHub. Because no test ran it, a card that still read the issue's text, or that counted anyone's approval, would have passed. I added two tests that run the real `card.gather` against a fake GitHub:

- **`test_the_card_fetches_only_the_bots_records_and_the_latest_commits_checks` (180.1).** The fake has bot records on both the issue and the PR, plus a person's comment pasting an approving review record. The issue's text holds a plan of its own, an older commit has failing checks, and the test file reads differently on main. The test checks that `gather` returns only the bot's four records in order, and only the latest commit's checks. It also checks that each "Verified by" line is read from the PR's latest commit, and that a different issue text changes nothing.
- **`test_only_a_code_owner_on_main_makes_the_approval_pass` (180.6).** CODEOWNERS names boss and second on main, but intruder on the PR's own commit. Approvals by "someone" and by intruder must not show as passed on the card; boss's approval must.

To make sure the tests can tell good from bad, I ran them against a sample `gather` I wrote just for this:
- The sample version passes both.
- Each of four broken versions fails with its own message: one takes pasted records, one treats every reviewer as an owner, one reads the old commit's checks, one reads test files from main.

**Two choices I made the worker must follow:**
- **How `gather` reads GitHub.** It must go through `gh`: either the REST API or `gh issue view`, `gh pr view` and `gh pr list`. The fake fails on any other call, naming 180.1. I wrote this into the test file's description.
- **Where code owners come from.** They now come only from the default branch. Otherwise a PR could name its own author an owner by editing CODEOWNERS. I added this to non-functional requirement 180.6.
