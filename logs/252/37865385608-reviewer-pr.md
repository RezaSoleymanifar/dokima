**What the code does now, one item per criterion:**
- **Recording links:** after the plan review approves, the plan's blocking links are written as GitHub's own blocked-by links. Links GitHub already has aren't added twice. Links the new plan dropped are removed. Links a person made by hand are left alone.
- **Cards:** this issue's card and the card of every issue a link was added to or dropped from are redrawn, each showing the link from its own side. Each card keeps a hidden list of the issues that link to it, so the link still shows when that card is redrawn later.
- **Loops:** if the links would make issues block each other, nothing is recorded and the river stops for the owner, naming every issue in the loop.
- **Where links come from:** only the approved, checked plan. A pasted record, a rejected plan or the review's own fields are never used.
- **GitHub errors:** if GitHub refuses or fails to record or remove a link, the river stops, naming the link and GitHub's reason, and autopilot doesn't start the worker.

**Two notes, not blockers:**
- If another issue's record can't be read while a card is being drawn, that issue's link is skipped with only a warning in the run log, so a card could quietly miss a link. Stopping instead would fit "fail closed" better.
- The redraw loop in `record_links` (`dokima/agent.py`) would read more clearly with brackets around the condition.
