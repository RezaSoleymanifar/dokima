> **Part of:** #280 A drift audit compares the repo's settings with what Dokima needs and tells me what's off
> 
> **User story:** The owner never has to remember the audit: it runs by itself every day, and the owner can run it any time from the workflow's Run workflow button.
> 
> **Acceptance criteria:**
> - One workflow runs the audit once a day on a schedule. ([source](https://github.com/dokima-dev/dokima/issues/280))
> - The same workflow has GitHub's Run workflow button, and no other trigger: no settings-change events and no new comment command. ([source](https://github.com/dokima-dev/dokima/issues/280))
> - The workflow's command reports a faked missing branch rule on a new Setup issue. Against a faked clean repo, it posts nothing. ([source](https://github.com/dokima-dev/dokima/issues/280))
> 
> **Non-functional:**
> - Runs never overlap: a second run waits for the running audit, in one queue for the repo. (Two audits at once could post twice or create a label twice.)
> 
> </details>
