- **Token (189.4):** the workflow uses the Dokima app's token from the keys environment and never `github.token`.

Nothing in the change falls outside the plan.

**Notes (not blockers)**
1. **One bad PR can stop the whole run.** Only a refused update is caught. If GitHub fails to say how far a PR is behind (for example, a PR from a deleted fork), or the comment itself fails, the run stops there. The PRs after it aren't updated, and only the failed run says why (`dokima/uptodate.py:44`, `:51`).
2. **You'll need to merge this one yourself.** The PR adds a workflow file, so autopilot won't merge it (AGENTS.md, step 6).
3. **Some comments may be noise.** A PR pushed to between the read and the update gets a "could not be updated" comment, even though the next merge to main will update it anyway.
