All 20 new tests fail today, and each fails because the feature is missing: there is no `dokima.budget` command yet, records have no budget, and no workflow reads it.

**Plan**
- **426.1:** An agent run's record shows both budgets in its footnote, e.g. `GraphQL 4,321 → 4,100` and `REST 4,987 → 4,950`. Its JSON record holds the four numbers. A run that stopped before its agent started shows them too.
- **426.2:** Every job that calls GitHub's API reads the budget before its first call and after its last, even when a step failed. That covers agent.yml's own steps and the other ten listed workflows. Each reading goes to the log and, as one JSON line, to a file uploaded with the run. The line names the workflow, the run, the time in UTC and whose key it is (`app`, or `github-token` for the repo's own token). No two files in one run share a name, so [#427](https://github.com/dokima-dev/dokima/issues/427) (the low-budget warning) can read them all back.
- **426.3:** When GitHub won't give the budget, the run still does its work. The log, the file and the agent's record say "could not be read" with GitHub's reason.
- **426.4:** The only call made is `gh api rate_limit`, which costs nothing from either budget.

**Scope:** a new `dokima/budget.py`, `dokima/agent.py` and the 11 workflow files. The issue explicitly asks for the workflow changes, so they are allowed here. `dokima/card.py` is not touched.

**Tests:** `tests/test_budget.py` runs the command against a fake `gh`. `tests/test_budget_record.py` checks the agent's record and footnote. `tests/test_budget_workflows.py` checks how each workflow is wired up. Before handing back, I wrote a throwaway version of the feature for one workflow (assign.yml): the tests passed with it, and each deliberate break I tried turned them red. I then reverted it, so the branch only adds the three test files.

**Choices that limit the worker or narrow the ask**
- The worker must use the command shape `python3 -m dokima.budget before|after KEY FILE` and the agent's file `$OUT/budget.jsonl`, because the tests call them by those names.
- In an agent run, the "after" reading is taken just before the record is written. The few calls after that (posting the record, moving the board card, starting the next stage) appear in that run's log and file but not in its record. This is listed as out of scope.
