**Blocker B1 (criterion 239.2), for the planner:** a helper or file docstring escapes the 15-word cap if its text starts on the line after the opening quotes.
- **Why:** the check reads only the literal first line, which is blank in that layout. I confirmed it: a helper docstring written that way with a 30-word line is neither listed nor rejected (`dokima/planner.py:356`).
- **Why new tests aren't affected:** the older rule that a new test's first line must be one sentence already rejects a blank first line.
- **Why the planner fixes it:** the 239.2 test only writes docstrings that start on the same line as the quotes, so it passes while the criterion is still not met.
- **Fix:** the planner adds that case to the 239.2 test for a helper and for the file docstring. The worker then makes the check read the first non-blank line.
