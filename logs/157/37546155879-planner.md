**Agent:** I planned #157 as a single user story, and the plan passes both hand-back checks. All 7 new tests fail today because the feature is missing, not because the tests crash. The other 128 tests still pass.

**Criteria (5, so no split):**
- **157.1:** A review.json or work.json with a missing required field, a field of the wrong type, or an item of the wrong shape is rejected. The reason names the field, the check never crashes, and a well-formed hand-back still passes, even with its optional lists left out.
- **157.2:** A work.json that skips one of the plan's criteria, or adds one the plan doesn't have, is rejected, and each reason names the criterion.
- **157.3:** A blocker is rejected, and the reason names the blocker, when:
  - it names no criterion;
  - its criterion isn't in the plan (`N.k` for a story, `S<s>.<k>` for a split);
  - its test is neither empty nor one of the plan's tests for that criterion.
- **157.4:** A rejected worker or reviewer hand-back posts one comment listing every reason, with a link to the run.
- **157.5 (non-functional, fail closed):** Every worker and reviewer run checks against the plan in its pack and the issue number. A missing or broken plan.json rejects the hand-back and is never treated as a pass.

**How the tests work:** They're in `tests/test_handback_check.py`. They run the real command the workflow will run, `python3 -m dokima.agent check review|work FILE PLAN N`, and check the exit code, the printed reasons and that there's no traceback. Every reject case has a passing case beside it. For 157.4 the test runs the real check and record steps and reads the comment they write. The 157.5 wiring test reads `agent.yml`, which the issue's context says must pass the plan and issue number. So the scope is `dokima/agent.py` and `.github/workflows/agent.yml`.

**One older test changed:** In `tests/test_agent.py`, the "at most three notes" case used four empty notes. Under 157.1 an empty note is a fault of its own, so the case now uses four well-formed notes. It still tests only the limit of three.

**Concern:** Most of 157.4 already shipped in #149 (commit 056bffa): every run posts its record as a comment, a rejected record lists its reasons, and the footnote links the run. Two gaps remain:
- a crashing check posts a traceback instead of reasons;
- the plan-aware reasons never reach the comment, because the workflow doesn't give the check the plan.

The 157.4 test fails today on that second gap.
