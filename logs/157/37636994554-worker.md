**Agent:** The hand-back checker now checks worker and reviewer hand-backs against the plan, and all 136 tests pass (`pytest -q`), including the 7 new ones for this issue. All 7 failed before I changed anything.

**What was wrong:** the old check looked at only a few fields. It crashed when a list held a string or a number where it expected objects. It never got the plan or the issue number, so it couldn't tell whether work lines or blockers matched the plan's criteria. The round check (`check-round`) crashed the same way.

**What changed:**
- **`dokima/agent.py`:**
  - **157.1:** every field of `review.json` and `work.json` is now checked against its prompt's shape: missing fields, wrong types, and items missing one of their parts. Each reason names the field. Fields the prompts don't mention are still allowed.
  - **157.2:** a `work.json` must give a line for every criterion in the plan and none for criteria the plan doesn't have. The criterion numbers come from the issue number.
  - **157.3:** a blocker must name one of the plan's criteria (`S<s>.<k>` for a split). Its test must be empty or one of the plan's tests for that criterion.
  - **157.5:** a `plan.json` that is missing, not valid JSON or not an object rejects the hand-back with a reason naming `plan.json`. So does calling the check without a plan and issue number.
  - The round check now gives a reason instead of crashing.
- **`.github/workflows/agent.yml`:** the plan review, PR review and worker checks now get `$PACK/plan.json $N`.
