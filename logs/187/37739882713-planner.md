The 11 new tests all fail today because the feature is missing, not from a crash. **The most important finding is a feasibility problem.** By every report I found, GitHub refuses to serve a job's log while that job is still running (it returns "not found" until the job ends). If that holds, the second machine can show the minutes but not the step until the agent has finished. The tests use a fake GitHub that does serve the log mid-run, so they can't catch this; only a real run will show it. The minutes are safe, because GitHub does serve the list of the run's steps and their start times while a run is in progress.

**The plan:**
- **On the agent's machine:** a small reporter runs beside the agent with no key and makes no calls to GitHub. About once a minute it writes `dokima-step: <step>` to the job's own log. Code picks the step from the agent's newest tool call, never from the model's words.
- **On a second machine (a new job in `agent.yml`, running alongside the agent's job):**
  - It holds the only key, which can write issue comments and read the run, nothing else, and is revoked when the job ends.
  - It works out the minutes from when the agent step started. It reads the step from the agent job's log when GitHub serves it, and shows the minutes alone when it doesn't.
  - It edits only this run's own live card, and only accepts the fixed step names, so a made-up line in the log can't reach the card.
  - It stops when the agent ends or the card has become the run's record, so the result is never overwritten.
- **Requirements beyond the card:** everything shown passes through `scrub()` first. A failed update never stops the agent or fails the run, and the result still gets posted.

There are 7 criteria (187.1–187.7) and 11 tests, all in `tests/test_progress_card.py`. This version replaces the previous round's tests in that file.

**The question for the owner:** is a card that shows only the minutes good enough while GitHub refuses the log? The alternative is getting the step to the second machine another way, such as uploading it as a file attached to the run. That would put the token used for those uploads on the agent's machine, and it's a larger change. The plan assumes the minutes alone are enough and adds nothing to the agent's machine. The concern in the plan sets out the same evidence.
