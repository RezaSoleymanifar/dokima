**User story:** On autopilot, an issue blocked by open issues is planned fresh once they merge, so nothing is ever built from a plan written before its blockers landed.

**Acceptance criteria**
- **353.1** On autopilot, an issue with an open blocker never starts its planner by itself. This is already true today, so I filed three existing tests under it instead of writing a new one.
- **353.2** If a plan is approved while a blocker is still open, nothing is built. The card's Next line names the open blockers, says the issue will plan again when they close, and mentions no one. The card stays in Plan without Needs you.
- **353.3** When the last blocker closes, a new planner run starts once, with `Autopilot: blockers merged, starting plan`. The worker never builds the old plan. A `/plan` or `/work` you type by hand still runs, and no later close overrides it.
- **353.4** The #253 code is gone: `WAIT_LINE`, `GO_LINE`, `worker_waits`, `start_worker` and `start_blocked_workers`. The bot's old "blockers closed" line no longer moves a card to Work, and AGENTS.md is rewritten to match, including dropping #343's "also while it waits on a blocker".
- **353.5** (non-functional, fail closed) If GitHub can't list an issue's blockers, nothing starts and the issue gives GitHub's reason. This holds both at plan approval and when another issue closes.
