**Agent:** A worker with nothing new to push now still opens its pull request. Both of the plan's tests pass, and so does the full suite (477 tests).

**What was wrong:** the push step in `.github/workflows/agent.yml` stopped with "Nothing to push." whenever the worker had no new changes. That happened before it reached the line that opens the pull request, so the PR was never opened. This is what happened on #244.

**The fix:** when there's nothing new, the step now skips only the commit and push. It then always goes on to the existing check, which opens a pull request from `try/issue-N` into `main` only for a worker, and only if none is already open. So a worker with no PR open always gets one, no PR ever opens twice, and a planner still never opens one.

**Things to know:**
- **A workflow file changed.** My instructions say a worker never edits `.github/`, but the approved plan names `.github/workflows/agent.yml` as the only file in scope, because that's where the early stop lives. I followed the plan. If code undoes changes under `.github/` before the judges see them, this fix is lost and the tests will fail again. Either way, the pull request changes a workflow file, so it will wait for your merge even on autopilot.
- **One gap the tests don't catch.** The plan reviewer noted that no test checks a worker whose hand-back was rejected. My fix keeps the PR step limited to passed hand-backs, so a rejected one still pushes nothing and opens nothing, but no test proves it.

The hand-back is in `/tmp/dokima-out/work.json` and passed both required checks.
