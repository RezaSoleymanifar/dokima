**Agent:** I fixed the open blocker, B3. All 243 tests pass, including the 5 for this issue; before the fix, the 176.3 test failed with "the agent started though its start should have failed".

- **B3 (`.github/workflows/agent.yml`):** The install step sends pip and npm output through `tee`. No shell is set, so GitHub runs the step as `bash -e` without `pipefail`. That means the step gets `tee`'s exit code (0), so a failed install never wrote its reason and the agent started anyway. I added `set -o pipefail` as the first line of the step, so a failed pip or npm now records its reason and the run stops before the agent.
- **Reviewer's note (`.github/workflows/commands.yml`):** Both reviewers noted that if the split-kind lookup failed during `/work`, the listener quietly treated the issue as a normal one and started the worker.
