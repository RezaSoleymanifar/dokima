**Agent:** I fixed blocker B4 and the hand-back passes both checks. The plan's criteria are unchanged; only the test harness changed.

**The problem:** `tests/test_start.py` ran every workflow step with `bash --noprofile --norc -eo pipefail`. GitHub runs a step that names no shell with plain `bash -e`, which has no pipefail. So when `pip` failed inside the install step's `| tee` pipe, the test caught it, but GitHub would not have.

**The fix:** a new helper, `github_shell`, picks the shell GitHub would actually use. It looks at the step's own `shell:`, then the job's defaults, then the workflow's defaults:
- No shell named anywhere: `bash -e`.
- `shell: bash`: `bash --noprofile --norc -eo pipefail`.
- Any other shell: the test refuses it, so no step ever runs under settings GitHub wouldn't use.

Both the agent workflow and the command listener now use it.

**Results:**
- Against the worker's current `agent.yml`, the 176.3 test fails with "176.3: the agent started though its start should have failed". That is the real bug the reviewer reported as B3: a failed install goes unnoticed and the agent starts anyway.
- Adding `set -o pipefail` to the install step makes all 5 tests pass. I put `agent.yml` back as it was, so fixing it is still the worker's job.
- All tests: 242 pass and 1 fails, the 176.3 test above.

**The hand-back** is in `/tmp/dokima-out/plan.json`:
- A reply to B4 marked "fixed".
- A `test_changes` entry giving the reason for changing the existing test.
- I dropped the old question, since you already answered it with "yes, cover both".
