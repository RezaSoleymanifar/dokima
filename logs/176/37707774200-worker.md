The bot can't push workflow changes, and most of this fix is in `agent.yml` and `commands.yml`, so you'll likely have to push it yourself, as the planner warned.

**What was wrong:**
- `agent.yml` only let the planner start without a `try/issue-N` branch. A split never creates one, so its plan review always failed.
- When a step before the agent failed, nothing reached the issue. The record step even scored the hand-back check that never ran as a pass.
- When the listener couldn't route a command or file a split's stories, the error only showed up in the run log.

**What changed:**
- **176.1 – plan review without a branch:** with no try branch, a plan review now starts from main. A pull request review still refuses to start without one.
- **176.2 – a split stops for you:** with 176.1 in place, a proposed split gets its plan review. After an approval it stops, mentions you and sets Needs you. Child issues are still filed only on your `/work`.
- **176.3 – failed starts say why:** five steps before the agent now record their reason: the code-owner check, the starting branch, building the pack, the install, and the pack check. A new "The agent starts now" step marks the point the agent begins. If a run fails before that point, it posts one "stopped before any agent started" record giving the reason. That record mentions you and starts nothing else. When a step left no reason, the record names the failed step from GitHub's own record of the run. A run whose agent did start posts only its own record, as before.
- **176.4 – failed commands say why:** the listener keeps GitHub's error when routing or filing fails. A new `say-why` job posts it, with the Next line, on the issue or pull request where you wrote the command. Comments from people who aren't code owners still get no reply, and commands that work post nothing extra.
- **176.5 – still a failed run:** a run that never started still ends as a failed run on GitHub after posting why.

**Changes in `dokima/agent.py`:**
- A new `not-started` record type and an `agent not-started` command that writes it.
