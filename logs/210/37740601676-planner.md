**What the plan promises (210.1–210.5):**
1. **The Autopilot pill.** An issue on autopilot shows the pill on its card, and so does its open pull request. The pill stays when the board or the river moves the card to another column. It goes away when the issue comes off autopilot, and issues that aren't on autopilot never show it.
2. **Splits.** Stories filed by a split under a parent on autopilot get the `autopilot` label and land in Backlog with the pill. The parent shows Autopilot in Work. Stories under a parent that isn't on autopilot get neither.
3. **Needs you takes its place.** When the river stops for the owner, the card shows Needs you instead of Autopilot, and Autopilot comes back when the river goes on. Switching autopilot on or off never hides or removes a Needs you, so a card never shows both.
4. **The Autopilot view.** Code adds one table view filtered to `label:autopilot` the first time an issue goes on autopilot, and never adds it twice. GitHub's REST API now supports creating project views, so this criterion is tested rather than left manual. For the view to list pull requests too, a pull request built for an issue on autopilot carries the label while its issue does.
5. **No board.** In a repo without a board, autopilot still switches on and off, splits still label their stories, and nothing fails.

**Design choices:**
- Autopilot is a second option on the same Action field that holds Needs you, so one card can't show both.
- The work goes in `dokima/board.py` (the board sync) and `dokima/agent.py` (moving cards and filing splits), plus the board section of `AGENTS.md`.
- `board.yml` doesn't change: it already runs on labeled and unlabeled issues and on pull requests opening. The plan says so explicitly, as the issue asked.
