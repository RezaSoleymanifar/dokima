**The problem:** one `/autopilot start` labels a whole tree within seconds, and each label starts its own board run. Those runs aren't queued behind each other, so each can see "no Autopilot view yet" and add one. The board would then end up with several Autopilot views.

- Only the board run for the top issue of the tree adds the view. That is the issue switched on whose parent is not on autopilot.
- `/autopilot start` labels each parent before its sub-issues, so a sub-issue's run always sees its parent already on.
- Stories filed later under a parent on autopilot add no view.
