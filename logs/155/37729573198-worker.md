**Agent:** The planner check for #155 is built, and the full suite passes: 285 tests, including the 15 plan tests that all failed before I started. The only file changed is `dokima/planner.py`, and the hand-back in `/tmp/dokima-out/work.json` passes both required checks.

**Cause:** the check never read test docstrings and never ran new tests. It also saw a rename as one deleted test plus one new test, and it crashed on a test file that wasn't valid UTF-8 text.

**What changed:**
- **Unreadable files (155.4):** before anything else reads them, every touched test file is checked as Python. Bad syntax or text that isn't valid UTF-8 is rejected with a reason naming the file.
- **Renames (155.3):** a test whose source is the same apart from its name now counts as a change under its old name. A rename with no reason under that old name is rejected, naming the old test. The new name is also kept, so the criterion the plan files it under still counts.
- **Summaries (155.1):** each new test's docstring must start with one sentence on one line, ending in `.`, `?` or `!`. A dot inside, like "1.5 s", still passes.
- **Must fail today (155.2):** each new test is run on its own on today's code. One that passes or is skipped is rejected, named, and the reason says it passes today. A failure or a missing-feature import error passes.
- **Hangs (155.5):** a new test still running after `NEW_TEST_TIMEOUT` (60 s) is stopped and rejected by name.

Changed older tests are neither run nor held to the summary rule.

**Worth knowing:**
- Because every new test is now run, the suite takes about a minute instead of 17 s.
- If a new test runs nothing at all (pytest exit code 5), it is rejected as passing.
- If pytest can't find the test by name (exit code 4), the test is treated as failing and gets through. I couldn't see how that would happen with a real test, so I left it.
