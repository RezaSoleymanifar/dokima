**Agent:** The work for #315 is built and all 760 tests pass locally (`pytest -q`). Before the change, the 9 plan tests failed and everything else passed. GitHub's checks still have to run. Since this changes workflow files, autopilot won't merge it: it stops for you to approve.

The cause matched your diagnosis. Every redraw shared the one `card` queue, and each card write edits the issue, which started another run in that queue. GitHub keeps only one waiting run per queue, so unrelated runs kept replacing the redraw that was waiting.

What changed:

- **When cards are redrawn (`card.yml`):** they now also redraw when the commands run finishes for a review on a PR (that's how your Approve shows up) and when a PR merges. A command typed in an issue comment, and the card's own edit of the issue, still redraw nothing.
- **One queue per issue and per PR (`card.yml`):** each issue and each PR has its own queue, and nothing cancels a redraw that is already running. Runs that draw nothing each wait in a queue of their own, so they never knock out a real redraw.
- **After a record is posted (`agent.yml`):** a new step redraws both cards right after the record goes up. It uses the copy of the card code taken from main, never the branch being judged. If the redraw fails, the run logs a warning and carries on.
- **After merge:** the merge redraw now gets the PR number, so both cards say Merged. They show Code review passed (linking its run) from the record on the PR, and Owner approval passed (linking the PR) when a code owner merged.
- **Criterion links (`dokima/card.py`):** only the first sentence of each criterion is the link; the explanation after it is plain text. A criterion with no check links nothing.
- **One-time fix of stale merged cards:** when this reaches main, a step runs `python3 dokima/card.py merged`. It goes through every merged PR that has a card and rewrites only the PR or issue card that no longer matches a fresh drawing. It runs again whenever `dokima/card.py` changes on main.

Two things to know:

- `tests/test_plan.py` forbids the word `pull_request_review` anywhere in `card.yml`. So the filter lets every commands run through except those started by an issue comment, which works out the same because the commands workflow listens only to issue comments and reviews.
- A sentence ends at `.`, `?` or `!` only when the next word doesn't start lowercase. That keeps `dokima.audit` whole, but a mid-sentence abbreviation followed by a capital, like "e.g. GitHub", would cut the link short.
