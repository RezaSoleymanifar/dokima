**Why PR #312's card went stale.** Its card is correct now: it was only redrawn later, by the tests that run on main after the merge. Two causes:

- **Waiting redraws get cancelled.** Every card write edits the issue, which starts another card run. All card runs share one queue, and GitHub keeps only one waiting run per queue, so each new run cancels the redraw that was waiting. This is the main thing that leaves cards stale.

**Acceptance criteria:**
1. **315.1:** Both cards are redrawn when a check finishes, an agent posts a record, you approve, or the pull request merges. A command typed in an issue comment, and the card's own edit of the issue, redraw nothing.
2. **315.2:** After a code owner merges, both cards say Merged with All tests, Code review and Owner approval passed. The code review is found on the pull request and links to its run; your merge links to the pull request.

5. **315.5 (non-functional):** Every redraw runs main's copy of the card code. A waiting redraw can only be replaced by a newer redraw of the same pull request or issue.
