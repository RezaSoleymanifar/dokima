**Agent:** I fixed reviewer blocker B1 on #315 and handed back a revised plan. Both hand-back checks pass.

**The blocker:** the queue test for 315.5 still passed if card.yml gave each issue or pull request number its own queue but put everything for that number in it. That mutant puts the bot's own edit of issue #40 in the same queue as the owner's edit of #40. Since every card write edits the issue, each write would cancel a redraw of that issue still waiting its turn, which is exactly the bug you reported.

**The fix, in `tests/test_card_redraw.py`:**
- The test now includes an owner's edit of issue #40 as a redraw.
- It checks that the bot's edit of #40 and a command typed in an issue comment never share that redraw's queue. If they do, it fails with "315.5: the bot's edit of issue #40 waits in the group … of a redraw of issue #40, so it cancels that redraw".
- Issue #40 must also have a queue separate from PR #5's. This matches the existing separation of issue #41 and PR #6, and your "each issue and pull request its own redraw queue".

**Checked against a temporary card.yml (restored afterwards):**
- With the reviewer's per-number queue, the test fails with the message above.
- With a fix that gives the bot's own edits a one-off queue of their own, it passes.
- On today's code, all 9 tests in the file fail because the feature is missing. The queue test fails because every redraw shares the single `card` queue.

**Plan changes:**
- The non-functional requirement 315.5 now says what you asked for in your `/plan` comment. Each issue and each pull request has its own redraw queue. A waiting redraw is replaced only by a newer redraw of the same one, never by another's redraw, the card's own edit of the issue, or a command.

- Everything else stays as in the last plan: criteria 315.1 to 315.4, scope, tests and links.
