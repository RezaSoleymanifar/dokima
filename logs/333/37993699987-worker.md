**What the scan does.** You run `DOKIMA_BOARD=org/N REPO=owner/name python3 -m dokima.scan`. It prints one line per problem card, naming it as "issue #N" or "PR #N":
- **Closed card in the wrong place:** it is outside Done or has a pill, and the line says where it sits and with which pill.
- **Open card in the wrong column:** it sits in a different column than its state gives, or in no column. The expected column comes from the board's existing rules, unchanged.
- **Stale card:** an issue or PR card that doesn't show the card Dokima would draw for its issue right now.
- **Card GitHub won't give:** named with GitHub's own reason. The other cards are still checked.

If it names anything, it ends with "N of M cards on the board are wrong." and exits 1. Otherwise it prints `All N cards on the board match their state.` and exits 0. If `DOKIMA_BOARD` or `REPO` isn't set, it says so and exits 1.

**It only reads.** To work out what a card should show, it repeats the reading steps of Dokima's card redraw and stops before saving. It never edits a body, comments, moves a card or sets a pill. A test confirms it writes nothing to GitHub.

**One choice of mine:** a pull request on the board that wasn't built for any issue gets only the closed-card check. Dokima draws no card for it and the board doesn't place it, so there's nothing else to compare.
