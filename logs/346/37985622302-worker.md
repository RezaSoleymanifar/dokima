**Agent:** Each issue's card redraws now wait in a queue of their own, so a redraw for one issue can no longer cancel another issue's. Both of the plan's tests now pass locally (`pytest -q tests/test_card_queue.py`: 2 passed); before the change both failed because every redraw shared the one queue `card`. The GitHub checks haven't run yet, so they're still the real proof.

The only file changed is `.github/workflows/card.yml`:
- **Shared queue removed:** the single workflow-wide queue `card` is gone.
- **New first job:** it works out which issue the event is about: from the issue itself, from the worker run's title (`worker for #N`), or from the pull request's `try/issue-N` or `work/issue-N` branch. It names the queue `card-<N>`.
- **Separate queues for the rest:** the 15-minute sweep gets `card-sweep`. An event with no issue gets `card-pr-<n>` if it has a pull request, otherwise `card-run-<run id>`.
- **Card-writing job:** it waits in that queue and never cancels the redraw already running, so GitHub keeps the newest waiting one.
- **Unchanged triggers:** the old condition for when a card is drawn now sits on the first job. Bot comments, comments on a pull request and a pull request closed without merging still draw no card.

The other test files that use `card.yml` give the same results before and after the change (29 passed, 35 skipped).

One limit: a pull request merged from a branch that isn't named `try/issue-N` or `work/issue-N` gets its own queue, not its issue's. Dokima's own pull requests always use those branch names.

Because this changes a workflow file, the pull request will stop for you to approve before it merges, even on autopilot. `work.json` is written and passes both hand-back checks.
