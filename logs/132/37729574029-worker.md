**Agent:** I fixed the bug: a failed run now leaves its card in its stage's column with Needs you, even when the run's "Decide what follows" step also fails. All three of the plan's tests passed, and the full suite passed (273 tests).

**Cause:** the "Move the card on the board" step (`python3 -m dokima.agent board`) reads `board.txt`, which only the "Decide what follows" step writes. When that step failed, for example on a GitHub 502, `board.txt` was missing and the board step crashed. The card stayed where it was, without the pill.

**Change:** one fallback in `dokima/agent.py`, inside `main()`'s `board` branch. When `board.txt` is missing or can't be read, the card is placed as if the river stopped for the owner:
- **Record present:** the card goes to the column for the stage in `record.json`, with Needs you.
- **No record either:** the column comes from the run's `ROLE` and `STAGE` settings. The card still gets Needs you and the step exits 0, which is criterion 132.2.

Runs that did decide still read `board.txt` as before, so a run that hands on to the next agent leaves the pill cleared.

The plan's tests all failed on the unchanged code, each with that missing-`board.txt` crash. `work.json` is in `/tmp/dokima-out` and passes both hand-back checks. The only file changed is `dokima/agent.py`, and there were no open blockers to answer.
