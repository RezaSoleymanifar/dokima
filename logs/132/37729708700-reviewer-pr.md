**Agent:** I approved the result for issue #132. The review is saved at `/tmp/dokima-out/review.json`, and both hand-back checks passed.

**What the worker changed:** one small change to the board step in `dokima/agent.py`. Before, when a run's "Decide what follows" step failed, the board step crashed because it found no file telling it where the card goes. Now it handles that case as a run that stopped for the owner:
- If the run wrote a record, the card goes to the run's own stage column with Needs you. So does its open pull request's card.
- If the run left no record at all, it takes the stage from the role the run was started for. The card still gets Needs you, and the step exits cleanly.
- A run that hands on to the next agent still writes its decision, so its pill stays cleared.

**What I checked:**
- **Tests fail without the fix:** with the old version of `agent.py` put back, all 3 new tests in `tests/test_failed_run_card.py` fail. One fails on the missing file, another lands in the wrong column. With the change they all pass.
- **Nothing else broke:** the full suite passes, 273 tests.
- **The planner's tests are unchanged:** the worker's commit touches only `dokima/agent.py`.
- **Worker runs land in Work:** when there is no record, the stage comes from the run's own settings. That setting is empty for every role except the reviewer, so a worker run correctly lands in Work.

**What I could not check:**

- The worker's session log held only a run summary, not the conversation. So I couldn't check whether the worker read the checkers to learn how to pass them. The change itself shows no sign of that.

**The one note:** the fix also treats a damaged decision file the same way as a missing one, which fits "fail closed". No test covers that case.
