**Agent:** I've built the retry for [#429](https://github.com/dokima-dev/dokima/issues/429) (board and card updates stopped by the empty API budget). All 10 of the plan's tests pass, and the 191 tests in the board, card and agent test files still pass. As instructed, I did not run the full suite.

**How it works.** When a board or card update fails, a new file, `dokima/retry.py`, reads GitHub's rate-limit endpoint (`gh api rate_limit`) right away. If the GraphQL or REST budget shows 0 left, it:
- prints a warning,
- waits until GitHub's reported reset plus 5 seconds (the later reset if both budgets are empty),
- runs the whole update once more from scratch.

If the second try fails too, the run fails as before and never waits again. Any other failure, or a budget GitHub can't report, fails at once like today.

**Where it's applied:**
- **`dokima/board.py`**: board.yml's event runs and 15-minute sweeps.
- **`dokima/agent.py`**: the board step at the end of every agent run. This follows the planner's reading that it waits too, so during an outage the next stage can start up to an hour later. You said `/work` with that reading in place.
- **`dokima/card.py`**: card.yml's redraws and its 15-minute sweeps. A sweep or redraw that reports failed cards counts as a failure, so it is retried too.

**One thing to know:** other tests that make a board or card update fail on purpose will now also call `gh api rate_limit`. If `gh` is missing or GitHub refuses, that counts as "not a budget failure" and the test fails as it did before. If `gh` is installed and logged in on the test machine, those tests make a real call to GitHub, which normally reports budget left. Those test files passed here.

The hand-back is in `/tmp/dokima-out/work.json`. It passes both checks after I shortened three docstrings the checker flagged as too long. There were no open blockers to answer, and I raised nothing new.
