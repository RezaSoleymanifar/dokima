**How it works.** When a board or card update fails, it reads how much budget is left from GitHub's rate-limit endpoint, which costs nothing. If the GraphQL or REST budget is at 0, it waits until GitHub's reported reset time and runs the whole update once more. That second run rebuilds everything from what GitHub shows at that point, so the cards end up right with no comment needed. The wait happens inside the existing steps, so no workflow file changes. The worker may change `dokima/retry.py` (new), `dokima/board.py`, `dokima/card.py` and `dokima/agent.py`. `card.py` is normally off limits, but the issue asks for card redraws to be retried, which needs it.

**Criteria:**
- **429.1:** a board update the empty budget stopped runs again after the reset. This covers event runs, the 15-minute sweeps and the board step at the end of each agent run.
- **429.2:** a card redraw or card sweep the budget stopped runs again after the reset, showing the issue as it is then.
- **429.3:** any other failure, or a budget GitHub can't report, fails at once as it does today, with no wait and no second run.
- **429.4:** the retry waits for the reset time (the later one if both budgets are empty) and runs only once more. If that fails too, the run fails rather than waiting again.
