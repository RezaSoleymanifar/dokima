> <details><summary>Original issue</summary>
> 
> The board is updated only when an event can change an item's column or pills, and a burst of events on one issue within a minute becomes one update.
> 
> Owner's words (2026-10-09): "Yes, update the board only when the column can change and run it on autopilot."
> 
> Why, measured 22:30-23:30Z on 2026-10-09: GitHub's GraphQL budget (5,000 an hour, shared by every Dokima workflow) was used about 3,600 times. Split by the workflow runs active each minute: board.yml about 56% (144 runs, about 2.4 a minute), card.yml about 19%, the full suite about 9%, all agents together about 10%, uptodate.yml under 1%. The budget ran out at 22:10Z the same day and stopped commands, cards and the board until it reset.
> 
> - An event that cannot change the column or a pill (for example an ordinary comment, a review comment, or a check run that is not a required check) does not run the board update.
> - Events about one issue that arrive close together cause one board update for that issue, not one each.
> - The 15-minute sweep stays as the safety net, so a skipped event never leaves a wrong column for long.
> - Same rule for card.yml where it applies: a card is redrawn only when something it shows changed.
> - The board and cards end up exactly as today; only the number of runs drops.
>
