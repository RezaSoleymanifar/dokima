**Agent:** I re-planned #205 as a split into five child issues, and the hand-back passes both checks. The owner confirmed every assumption from the first round, so the plan has no questions left. There were no open review comments (blockers) to answer.

**What changed this round:** your new requests for how you see autopilot became their own story (story 2). The first version of the story that turns autopilot on and off would have grown past five criteria, so I split the original story 1 in two. To stay at five stories, two old stories are now one: children starting once their blockers merge, and the tree switching itself off when it's done. Both happen when an issue closes.

**The five stories:**
1. **Switch on and off:** `/autopilot start` and `/autopilot stop` work on an issue or its pull request and cover everything under it. Only a code owner's comment counts. Neither command starts a stage by itself, and one comment names every issue that was switched.
2. **What you see:**
   - An Autopilot pill on every card in the tree, including children a split files later.
   - The pill reads "Autopilot needs you" when the river stops for you.
   - A board view lists everything on autopilot.
   - Each issue's card says "On autopilot from #N", so a child shows where it came from.
   - A repo without a board still works.
3. **Approved plan goes on:** an approved plan starts the worker and an approved split files its children, including ones already waiting when autopilot starts. Autopilot still stops on questions, escalations, three blocking reviews in a row, a rejected hand-back, and a run that failed or never started. Each stop says why and mentions you.
4. **Approved pull request merges:** it merges once the reviewer approves and every check is green. A refused merge stops for you with GitHub's reason, and a pull request that changes a workflow file never merges by autopilot.
5. **Children start, then the tree ends:** each child starts planning once everything it waits on has merged. When the last child closes, the parent closes and autopilot clears across the tree.

Stories 2 to 5 each depend on story 1.

**Two things you should know:**
- **The board view may need a one-time setup step.** I'm not sure GitHub's API can create a project board view. The story 2 planner is told to check, and to mark that criterion as a manual check if it can't.
- **Concerns I raised:**
  - Every story needs changes in `.github/workflows/`, and story 2 also changes `dokima/card.py`. AGENTS.md only allows that when the issue asks, so each child should say so in its own words.
  - Story 5 overlaps #86 (start children when blockers merge). I recommend story 5 absorbs it and #86 is closed as a duplicate.
