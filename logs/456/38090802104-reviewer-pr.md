The last round's fix works:
- A backtick inside a link's address, or a single backtick as a raise's label, no longer lets an agent's words draw HTML.
- The worker left the planner's tests alone. The 12 tests in `tests/test_code_as_written.py` pass when I run them, and code's full run shows 958 passed.

**What's still wrong:** `raise_line` in `dokima/card.py:316` now keeps the line breaks in a raise's label. So a label with a code block in it opens that block at the left edge of the comment, and the block never closes. The fence of the raise's own words then closes it instead, and the text inside the words' code block comes out as raw HTML, so an agent's `<kbd>evil</kbd>` would be drawn. On main the label is joined onto one line and escaped, so this is something the change breaks.

I couldn't confirm this on GitHub's real rendering because the sandbox has neither GitHub access nor a markdown renderer. It rests on GitHub's markdown rules: a closing fence can't have anything after it but spaces.

I raised two blockers:
- **For the worker:** draw the label on one line again, as main does, so it can never hold a code block.
- **For the planner:** add a test case with a label that is a code block, because the current tests only try one-line labels. Code will send it back to the planner first.
