**The blocker:** in two cases Dokima now treats text as code when GitHub doesn't, so it no longer escapes it. Plain words should still show HTML as text (criterion 2), and here they don't:
1. **Backticks with a blank line between them.** GitHub never lets code run across a blank line. So in a criterion like ``Run `a`` + blank line + ``<img src=x>` now``, the `<img src=x>` line reaches GitHub raw and the image draws. I checked this with the plan's own card-drawing helper.
2. **A backtick with a backslash in front.** GitHub shows `` \` `` as a plain backtick and never starts code there. So ``Run \`<img src=x>\` now`` is also left unescaped and draws.

On `main`, both come back escaped (`&lt;img src=x&gt;`). The fix is for the planner to add tests for these two cases. The worker then makes code stop at a blank line and ignore a backtick that has a backslash before it.

**The worker's raise:** an unclosed ``` fence stays escaped even though GitHub shows the rest as code. I confirmed that, plus two related cases (a `~~~` fence, and a ```` fence closed by a shorter ```), and agreed it belongs in its own issue. In all three you see `&lt;` where `<` was written, but no HTML draws. Per the worker's record it's already filed.
